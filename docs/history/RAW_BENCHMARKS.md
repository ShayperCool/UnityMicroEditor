# Замеры сырого проекта

2026-10-05, Unity `6000.6.3f1`, Linux Mono, AMD Ryzen 7 5700X3D, NVIDIA RTX 4060, OpenGL Core, NVIDIA driver `580.178.04`. Проверочная RawSample содержит камеру, realtime свет, вращающийся primitive cube, prefab override, Material, PNG, ScriptableObject и пользовательский MonoBehaviour.

Все графические прогоны выполнены в существующей desktop session при 960×540 и ограничении 60 FPS, без VSync, по 120 кадров. Прежняя Dungeon SampleScene продолжала работать отдельным процессом. Числа относятся к маленькой проверочной сцене, их нельзя переносить на полный Dungeon.

## Старт и изменения

| Проверка | Подготовка исходников | Из неё compiler или cache | Player до готовой сцены | Подготовка плюс старт |
| --- | ---: | ---: | ---: | ---: |
| Первый запуск, пустой C# cache | 0.857 с | 0.834 с | 3.098 с | 3.956 с |
| Повтор 1 | 0.251 с | 0.225 с | 3.169 с | 3.419 с |
| Повтор 2 | 0.239 с | 0.212 с | 3.165 с | 3.404 с |
| Повтор 3 | 0.273 с | 0.238 с | 3.162 с | 3.434 с |
| Изменение C# | 0.884 с | 0.859 с | 3.124 с | 4.008 с |
| Изменение сцены и ассетов | 0.234 с | 0.211 с | 3.092 с | 3.326 с |

Медиана повторного запуска с кэшем: 3.419 с. Готовность отмечается после первого завершённого кадра активной сцены. Число справа складывает измеренную подготовку и старт native процесса до ready marker; полное время команды включает ещё GPU preflight, наблюдение за 120 кадрами и остановку.

Первый прогон имеет пустой кэш нашего compiler. Кэш ОС, Unity shaders и NVIDIA driver уже прогрет предыдущими проверками. Это не замер после перезагрузки машины.

В C# изменился `CodeRevision` с 1 на 2. При изменении контента одновременно проверены scene revision 1→2, ScriptableObject revision 7→8, material red channel 0.2→0.75, prefab scale Y 1→1.25 и PNG pixel white→red. Prefab instance сохранил исходный override X=1.5. Новые значения пришли из лога реально загруженного пользовательского скрипта. Code cache при изменении ассетов остался попаданием.

## Автоматическая итерация

Отдельный живой запуск `--watch` проверил обнаружение изменений и поведение при ошибке:

| Событие | Результат |
| --- | --- |
| Ошибка синтаксиса C# | Прежний PID продолжил работать, revision не заменена |
| Исправление C# и новая версия | 4.925 с от записи файла до ready marker нового процесса |
| Изменение ScriptableObject | 4.022 с от записи файла до ready marker; C# cache hit |
| Ctrl+C | CLI завершился с 130 и остановил собственный Player |

Эти времена включают обнаружение, подготовку новой revision, остановку предыдущего процесса и старт следующего. Каждый вариант измерен один раз. Состояние игры сбрасывается. При ошибке уже в native runtime автоматического rollback нет.

| --- | ---: |

| RAM PSS | 189.1–189.7 MiB |

Sampler читает только native Player PID примерно каждые 100 мс. Roslyn, Python, desktop и другой запущенный Player сюда не входят. RSS включает разделяемые страницы, PSS распределяет их между процессами. GPU memory показывает per-process allocation NVML. Сумма ресурсов нескольких инстансов может отличаться из-за shared memory.

Проверка со screenshot дала около 269 MiB RSS; основной benchmark выполнялся без захвата изображения. Разница не включена в диапазон выше. Screenshot проверил аппаратное изображение, backend был OpenGLCore и device RTX 4060.

## Отсутствие Editor и cooked контента проекта

Перед тестами создан отдельный source project без `Library` и `Builds`. Они не появились после всех изменений. Host executable, native library, host manifest, DLL и Player data проверены SHA до и после итераций и остались неизменными.

Дополнительный графический запуск с пустым compiler cache выполнен через `strace -f -e trace=execve`. Путь Editor executable намеренно указывал на несуществующий `NO_EDITOR_PROCESS_ALLOWED`, соседний SDK Data оставался доступен. Сцена успешно исполнила кадры. Успешные exec ограничились Python launcher, SDK dotnet/Roslyn, glxinfo, universal Player и localectl. Unity Editor не запускался.

Однократная первая успешная подготовка universal host заняла 28.068 с, BuildPipeline сообщил 9.990 с; итоговый host около 167.1 MiB. Эти затраты относятся к подготовке инструмента, не к импорту входного проекта. Последняя инкрементальная подготовка после исправлений runtime заняла 18.108 с.

`raw-run --headless` с этой material scene не проходит: в Null graphics device `Shader.Find("Standard")` возвращает null. Графический путь проверен. Headless сцены с таким контентом требуют отдельной адаптации; результаты headless не подменяют GPU замеры.

## Полная Dungeon SampleScene, 2026-10-06

Гибридный запуск настоящей `Assets/Scenes/SampleScene.unity` проверен на Unity `6000.6.3f1`, Linux Mono, Ryzen 7 5700X3D и RTX 4060 через OpenGLCore. Сцена и текстовые префабы восстанавливаются нашим loader из исходников. Модели, анимации, аудио и остальные поддержанные тяжёлые зависимости загружены из кэша Unity importer. Каталог содержит 13 460 native объектов, content pack занимает около 113.3 MiB и не содержит сцен.

Все семь прогонов завершили 120 кадров без ошибок и исключений при 960×540, 60 FPS и выключенном VSync. Это измерение полной подготовки и перезапуска Player. Обнаружение правок через `--watch` и изменение кода внутри уже работающего процесса в этой серии не измерялись; состояние игры при перезапуске сбрасывается.

Пересобраны `Dungeon.Runtime`, `Dungeon.ShipGen`, `Dungeon.Net` и `Assembly-CSharp`; ещё девять сборок взяты из кэша. Новый Player исполнил версию 2. При последующем изменении только сцены и WAV переиспользованы все 13 сборок.

Проверочный MonoBehaviour добавлен только в копию SampleScene. Через сериализованные ссылки он получил настоящий `Dungeon.DungeonShootingTarget`, Transform объекта `Floor` и импортированный `AudioClip`. При правке сцены код прочитал новую локальную позицию Floor `{x: 0.125, y: -0.25, z: 0}` вместо `{x: 0, y: -0.25, z: 0}`. Native cache остался попаданием, Editor не запускался.

Для тяжёлого ассета изменены первые 4096 PCM значений в копии `Assets/Dungeon/Audio/Packs/land_grate_0.wav`. Размер файла и настройки импортера сохранены. Полные 206.004 с включают эту пересборку, подготовку и старт Player; они не показывают стоимость только декодирования одного WAV. ## Обновление сцены в одном Player, 2026-10-06

Настоящая Dungeon `SampleScene` теперь обновляется через `raw-run --watch` в уже работающем Player. Unity Editor не запускался. Native content pack остаётся в памяти, а loader создаёт новый граф сцены, восстанавливает ссылки и callbacks, переключает активную сцену и выгружает предыдущую. Состояние объектов сцены сбрасывается при каждом обновлении.

Замер выполнен на той же RTX 4060 через OpenGLCore, Unity `6000.6.3f1`, Linux Mono, 960×540, с целевыми 60 FPS и выключенным VSync. Проверены три правки Transform объекта Floor, три добавления GameObject и три изменения собственного raw ScriptableObject. Каждая правка записана только в изолированную source-копию. Скриншоты во время замеров не снимались.

### От записи исходника до готового кадра

Основная метрика включает обнаружение правки watcher, подготовку immutable manifest и runtime reload. Runtime подтверждает новую revision после завершённого GPU кадра. Проверочный MonoBehaviour дополнительно читает реальные загруженные значения через сериализованные ссылки после `WaitForEndOfFrame`. Итоговое время берёт более позднюю из этих двух отметок.

| Правка | Три измерения до кадра и proof | Медиана | Подготовка, медиана | Runtime reload, медиана | Watcher и остальное, медиана |
| --- | --- | ---: | ---: | ---: | ---: |
| Floor Transform | 4.656 / 4.572 / 4.637 с | **4.637 с** | 2.425 с | 1.884 с | 0.328 с |
| Добавление GameObject | 4.428 / 4.935 / 4.975 с | **4.935 с** | 2.386 с | 1.886 с | 0.570 с |
| Raw ScriptableObject | 4.393 / 4.411 / 4.404 с | **4.404 с** | 2.306 с | 1.892 с | 0.213 с |

Медианы отдельных этапов посчитаны независимо, поэтому их сумма может отличаться от медианы полного времени. Runtime reload содержит создание всего графа, сериализацию, lifecycle, первый кадр и завершение выгрузки старой сцены. Это пока полная замена сцены; существующий Transform не правится на месте.

Предыдущая правка Transform с перезапуском Player занимала 23.032 с без измерения watcher detection. Текущая медиана 4.637 с уже включает обнаружение правки и подтверждение кадра, то есть примерно в пять раз меньше. В промежуточной реализации persistent Player времена были 8.522 / 8.429 / 8.480 с для Transform / GameObject / raw SO. Полный обход путей watcher добавлял около четырёх секунд. После замены обхода на общий `scandir` inventory это время исчезло; промежуточная серия сохранена отдельно и не смешана с финальной.

При обычных правках контента компилятор переиспользуется, GUID index и разобранные YAML берутся из session cache. В последней правке SO cache прочитал только изменённый `.asset`, 248 байт, и разобрал один YAML документ. 23 YAML документа и GUID index переиспользованы. C# этап занял 0.0058 с; импорт тяжёлых ассетов отсутствовал. Источник новых GameObject, значений Transform и SO остаётся в исходных файлах проекта.

### Проверка одного процесса и ассетов

Все девять обновлений выполнил один PID **3276822**. `rawReloadCount` последовательно вырос с 0 до 9. `nativeLoadCount` остался равен 1, `nativeObjectCount` равен 13 460. SHA digest идентификаторов всей native registry и EntityId конкретных AudioClip, Mesh, Material и Texture2D не изменились. Новые сцены использовали те же native объекты.

Проверочный код прочитал позиции Floor X=0.125 / 0.250 / 0.375, затем точные ссылки и имена трёх добавленных GameObject, затем SO revision 2 / 3 / 4. Ссылки на объекты восстановлены уже в `Awake`; игровые компоненты также выполнили свой `Awake`. Runtime проверяет SHA manifest из запроса; ack подтверждает request ID, revision, имя активной сцены `SampleScene`, тот же PID и нулевые ошибки и исключения.

Финальный runtime report содержит 1 560 кадров, девять reload, `success=true`, `errors=0`, `exceptions=0`. Средний FPS по всей серии составил 36.2 при target 60, поскольку создание сцены занимает main thread примерно на 1.9 с при каждой правке. Этот замер не утверждает непрерывные 60 FPS во время reload. CLI и его Player после проверки остановлены. SHA исходного Dungeon и reusable host сохранились; во входной source-копии не появились `Library` и `Builds`.

Изменение raw SO относится к `.asset`, который восстанавливает наш loader. Изменение ассета, уже включённого в native-каталог, например импортированной модели, анимации, WAV, текстуры или материала, по-прежнему требует Unity import и безопасного перезапуска. Изменение C# или состава сборок тоже переключается на подготовку и перезапуск. Их скорости этой серией не измерялись.

### Начальный запуск и память

Перед финальной серией сохранён C# cache предыдущего успешного прогона и те же физические пути source и package файлов. Начальный запуск нового CLI занял **23.988 с** до первого кадра. Первичная проверка и подготовка заняли 12.824 с, из них compiler cache validation 3.425 с. Скомпилировано ноль сборок, переиспользованы все 13 DLL. Native content pack уже подготовлен, кэши ОС и GPU не очищались. Быстрый session cache действует на последующие правки внутри этого запуска; новое выполнение CLI пока повторяет полную начальную проверку.

369 измерений native PID от ready до завершения серии, около 42.97 с, дали следующие значения. Python, compiler и Editor сюда не входят; shutdown исключён.

| Метрика | Минимум / среднее / максимум |
| --- | ---: |
| RSS | 796.8 / 862.5 / 890.1 MiB |
| PSS | 791.7 / 857.5 / 885.1 MiB |
| VRAM по NVML PID | 250.4 / 263.1 / 300.4 MiB |
| CPU за окно с reload | В среднем 57.6% одного core |

Первые десять samples имели средний RSS 798.5 MiB, последние десять 875.6 MiB. Это наблюдение роста памяти в короткой серии, а не доказательство утечки или её отсутствия: GC и idle после серии не контролировались. CPU также включает работу по пересозданию сцены, поэтому его нельзя сравнивать напрямую с idle или прежним двухсекундным steady окном. NVML действительно перечислил PID Player; софтверный рендерер не использовался.

### Повторение замера

```bash
python3 $UNITY_MICRO_EDITOR_ROOT/benchmark_scene_reload.py \
  --output Temp/UnityPlay/scene-reload-benchmarks/repeat \
  --runs 3
```

Нужен новый output directory, существующий hybrid host и актуальный опубликованный native-каталог. Новая копия имеет пустой C# cache, поэтому её первый запуск нельзя сравнивать с финальным тёплым начальным запуском 23.988 с.
